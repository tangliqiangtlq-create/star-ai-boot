### 关键决策点：为什么不选 RN / Flutter？

| 问题 | 影响 |
|------|------|
| **重复造轮子** | RN 有自己的 Navigation、Gesture、List 系统；hls.js 不能直接用，要换 `react-native-video` + 自己实现试看逻辑；Tailwind 不能用，要换 NativeWind |
| **SEO 彻底丢失** | 单页应用无法被搜索引擎索引，视频站主要流量来自搜索 |
| **开发者体验割裂** | RN/Flutter 的热重载比 Web 慢，调试工具弱，前端团队需要学两套 |
| **CI/CD 复杂** | RN 原生构建需要额外的 CodePush/Over-the-Air 更新，Flutter 也有类似问题 |

### 为什么不选 Cordova？

> Cordova 2025 年已 **正式归档停止维护**（Apache 基金会决定），旧插件体系，不推荐新项目。

### Next.js 15 App Router 的三个渲染策略

| 页面 | 渲染方式 | 原因 |
|------|---------|------|
| `/` 首页 | SSG（静态生成） | 内容不频繁变，极致性能 + CDN 缓存 |
| `/browse` 剧集列表 | SSR（服务端渲染） | 需要按 region/分类动态返回，且需要被搜索引擎收录 |
| `/video/[id]` 视频详情 | SSR（服务端渲染） | 核心转化页，需要返回 **解锁选项组合** 动态数据 |
| `/creator/dashboard` | CSR（客户端渲染） | 需登录 + 个人数据，SEO 不重要 |
| `/subscription` | SSR（服务端渲染） | 展示会员方案，需要按 region 返回不同价格 |

### hls.js 视频播放器关键处理点

```
hls.js 是 WebView 里唯一靠谱的 HLS 播放方案:

1. 签名 URL 刷新:
   签名 URL 15min 过期 → 播放时监听 Hls.Events.MANIFEST_PARSED
   → 每隔 10min 重新向服务端请求新 URL → hls.loadSource(newUrl)

2. 试看逻辑:
   video.currentTime >= preview_sec → video.pause()
   → 显示付费墙遮罩 (组件 VideoPlayer 内已实现)

3. Capacitor WebView 适配:
   capacitor.config.ts → androidScheme: 'https'
   → allowsInlineMediaPlayback: true (默认)
   → play inline (非全屏跳原生播放器)

4. iOS Safari 策略:
   iOS 17+ 强制用户手势触发 play()
   → VideoPlayer 组件加点击覆盖层处理 autoplay
```

## 五、对接 JeecgBoot 后端的三个坑

### 坑 1：Sa-Token Token 格式

JeecgBoot 默认用 `X-Access-Token` Header，不是 `Authorization: Bearer xxx`。**两个都发**：

```typescript
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('X-Access-Token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
    config.headers['X-Access-Token'] = token;  // 必须
  }
  return config;
});
```

### 坑 2：CORS 跨域

Nginx 反代或 JeecgBoot 配置：

```yaml
# application.yml
jeecg:
  cors:
    allowOrigin: "*"
    allowMethods: GET,POST,PUT,DELETE,OPTIONS
    allowHeaders: "*"
```

### 坑 3：Capacitor 壳内 Cookie 不同源

Capacitor WebView 内 `localhost:3000` 和后端 `api.starai.video` 不同域 → Cookie 不能自动带。**用 localStorage 存 Token**（已在 auth.ts 实现）。

```

  GitHub Actions → next build + next export → ./out/
  → rsync 到服务器 → Nginx 热更新 (原子替换)
  → CloudFront 缓存刷新

iOS App:
  GitHub Actions → next build + export → cap sync ios
  → fastlane gym → TestFlight → App Store

Android App:
  GitHub Actions → next build + export → cap sync android
  → fastlane gradle → Google Play

密钥管理:
  GitHub Secrets: APPLE_ID / ANDROID_KEYSTORE / STRIPE_WEBHOOK
  → 注入到各平台配置
```

## 七、备选方案对比 (风险兜底)

如果 Capacitor 方案遇到不可接受的性能问题（视频播放卡顿、WebView 内存泄漏），**降级预案**：

| 预案 | 触发条件 | 操作 |
|------|---------|------|
| **纯 H5 + PWA** | App Store 拒审 WebView-only 应用 | 去掉 Capacitor，纯 PWA（`manifest.json` + Service Worker），iOS 用"添加到主屏幕" |
| **RN 重写核心播放页** | WebView 视频性能差 | 首页/列表保留 Next.js SSR，只有 `/video/[id]` 播放页用 RN 原生重写 |
| **Tauri 替换** | 需要更好的原生能力（推送、文件系统） | 用 Tauri 2 + Next.js 15 替换 Capacitor，Rust 层处理推送 |

## 八、最终决策

```
选定: Next.js 15.0.3 + Capacitor 6.1.2 + React 19 RC + Tailwind 3.4
仓库: star-ai-app (独立 Git 仓库, 不在 star-ai-boot Maven 里)
理由:
  ✅ 一套代码覆盖 Web + iOS + Android + PWA
  ✅ SSR/SSG 保证 SEO (视频站核心流量入口)
  ✅ hls.js + Capacitor 方案在 2025-2026 年已非常成熟
  ✅ React 生态最丰富，Tailwind + Zustand + react-hook-form 搭配无敌
  ✅ 团队已有 React 经验，学习成本最低
  ✅ 后续可渐进升级: Next.js → Tauri, 或播放页 → RN
```
