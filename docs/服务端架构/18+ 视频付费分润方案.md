# 18+ 视频付费分润平台 · 架构方案

> 版本：v1.2.1 | 最后更新：2026-10-11 | 适用：全平台 18+ 内容，日活 1000，国内 + 国际双 Region
>
> **v1.2 核心变更**：每集定价 + 定价权开放给创作者 + 平台固定点数抽成（不同创作者点数独立配置）+ 剧集打包解锁
> · 创作者可自助设 price_amount，平台设置区间 + 自动风控审核
> · 抽成比例 creator_account.revenue_rate 独立可配（L1 默认 30%，爆款创作者可谈 50%+）
> · 发布时固化抽成快照到 stream_video.revenue_rate_snapshot，后续改比例不追溯
> · 剧集 stream_video_collection 支持剧集打包价，解锁后自动授予所有集观看权限
> · stream_video_purchase 修复剧集解锁唯一约束 + 加 unlock_scope/paid_amount 字段
>
> **v1.1 变更**：会员订阅池分润模式（Netflix 式），与原有交易驱动模式并存

## 一、方案定位

### 1.1 业务场景

| 角色 | 能力 |
|------|------|
| **用户（消费者）** | 注册强制成年验证 → 浏览/搜索视频 → 试看 → 付费购买 → 鉴权播放 → 断点续播 → 点赞收藏 |
| **创作者** | 入驻（KYC）→ 上传视频 → 自动审核 → 发布 → 数据看板 → 收益查看 → 提现申请 |
| **平台运营** | 视频人工审核 → 创作者等级管理 → 分类/标签管理 → 分润比例配置 → 提现审核 → 结算对账 |

### 1.2 设计约束

| 约束 | 说明 |
|------|------|
| **全平台 18+** | 不考虑普通/非18+ 内容并存，架构大幅简化 |
| **日活 1000** | 轻量部署，单实例主备即可，不追求极致高并发 |
| **国内 + 国际** | Region 路由（cn / sg / us），存储、CDN、支付渠道按 Region 切换 |
| **付费分润** | 用户付费 → 平台抽成 → 创作者分润，每月结算 + 提现审核 |
| **安全合规** | 18+ 签名 URL 强制鉴权 + 地理屏蔽 + 自动审核 + 审计日志 |

### 1.3 新增 vs 复用

| 分类 | 新增 | 复用 |
|------|------|------|
| **微服务** | payment（支付公共服务）、stream（视频消费域）、creator（创作者中心） | system / billing / task / provider / generate / content / team |
| **对象存储** | stream-creator-draft / stream-published / stream-temp 三个 bucket | 已有 MinIO 基础设施 |
| **转码** | FFmpeg Worker（独立进程） | 可后续切阿里云 VOD / AWS MediaConvert |
| **支付渠道** | 微信 Native / Stripe Checkout（先接这两条） | 复用 Sa-Token 鉴权 |
| **KYC / 年龄验证** | 新增 sys_user_age_verification 表 | 复用 system 模块 KYC 流程 |

```
══════════════════════════════════════════════════════
```

### 4.2 CDN 配置

| Region | CDN | 访问策略 |
|--------|-----|---------|
| **国内** | 阿里云 CDN / 腾讯云 CDN | MinIO presigned URL（时效 15min + IP 绑定 + Referer 防盗链） |

### 4.3 状态流转（上传 → 发布）

```
创作者上传
    │
    ▼
[stream-creator-draft]        ← 原始文件暂存
    │
    │  FFmpeg 转码 (独立 Worker)
    │  自动审核 Pipeline
    ▼
  video.publish_status = pending_review
  video.auto_review_status = passed / flagged / rejected
    │
    ├── auto_review_status = passed
    │   → 自动通过
    │
    ├── auto_review_status = flagged (0.85-0.90 灰色区间)
    │   → 人工复核
    │
    └── auto_review_status = rejected (nsfw > 0.90)
        → 直接驳回
    │
    │  通过 → COPY draft → stream-published
    ▼
  video.publish_status = published
  前端可见，CDN 分发

创作者下架
    │
    ▼
  video.publish_status = unpublished
  → 前端不可见
  → published bucket 资源保留 30 天后清理
```


## 四.五、消费路径与定价规则（v1.2 核心）

### 4.5.1 五种消费路径

```
用户看某视频时, stream-service 按以下优先级判定观看权限 (从上到下首个命中即放行):
═══════════════════════════════════════════════════════════════════════════

① 免费视频
   stream_video.price_type = 'free'
   → 所有人可看 (18+ 年龄验证 + Geo-Restriction 通过后)

② 会员免费 (订阅池模式)
   stream_video.price_type = 'member_only'
   AND 当前用户是 active 订阅会员 (stream_user_subscription.status='active')
   → 免费看, 贡献计入订阅池月度分摊
   实时校验, 不需要在 stream_video_purchase 插记录

③ 剧集解锁 (剧集打包) 🆕 v1.2
   用户已购买 stream_video_collection (stream_video_purchase.unlock_scope='collection')
   AND 该视频属于此 collection (stream_video_collection_rel 关联)
   → 自动授予该视频观看权限
   前端展示: "单集 ¥15 / 全集 ¥199 (共 16 集, 省 ¥41)"

④ 单集购买 (交易驱动)
   stream_video.price_type = 'paid'
   AND stream_video_purchase 有该 user_id + video_id 的有效记录
   → 永久观看 (默认 expires_at=NULL)
   有 preview_sec 秒试看, 超过后需要购买

权限校验伪代码:
  def has_watch_permission(user, video):
    if not user.is_adult_verified(): return DENY
    if video.is_geo_blocked(user.country): return DENY

    # 0. 全局免费集数 (平台配置: stream_platform_config.free_episodes_per_series)
    #    非会员也能免费看每部剧集前 N 集
    global_free_n = PlatformConfig.get('free_episodes_per_series', region=user.region, default=3)
    if video.is_in_series and video.episode_number <= global_free_n:
        return ALLOW(preview=0, free_type='global_free_episode')

    # 1. 会员权益: price_type='member_only' + active 订阅 → 完整免费
    if video.price_type == 'member_only' and user.has_active_subscription():
        return ALLOW(contributes_to_pool=True, free_type='member')

    # 2. 会员权益: 集级免费扩展 (叠加全局)
    #    会员在全局免费 N 集基础上 +X 集 (plan.free_episode_extra)
    if user.has_active_subscription():
        plan = user.subscription.plan
        member_free_upper = global_free_n + plan.free_episode_extra
        if video.is_in_series and video.episode_number <= member_free_upper:
            return ALLOW(preview=0, free_type='member_free_episode_extra')

    # 3. 会员权益: 秒级试看扩展 (叠加创作者设的 preview_sec)
    #    plan.preview_sec_extra > 0  → preview_sec + extra
    #    plan.preview_sec_extra == -1 → 完整免费看 (等同 member_only 效果, 但 price_type 仍是 paid)

    # 路径③: 创作者全局解锁 🆕 v1.2
    # 独立表 stream_creator_unlock, 解锁后该创作者所有视频 (含未来新发布的) 永久可看
    if video.creator.global_unlock_enabled        and CreatorUnlock.exists(user, video.creator_id)        and not CreatorUnlock.expired(user, video.creator_id):
        return ALLOW(unlock_source='creator_global')

    # 路径④: 剧集解锁
    cols = video.collections  # 该视频所属的所有剧集
    for c in cols:
        if Purchase.exists(user, collection=c, unlock_scope='collection'):
            return ALLOW(unlock_source='collection')

    # 路径⑤: 单集购买
    p = Purchase(user, video)
    if p and not p.expired():
        return ALLOW(unlock_source='episode')

    # 未解锁 → 返回试看 + 购买引导
    # 引导选项 (前端展示):
    #   - "买这一集 ¥15"      (单集购买)
    #   - "解锁整部剧集 ¥199"     (剧集打包)
    #   - "解锁该创作者全部 ¥X" (全局解锁, global_unlock_enabled=1 时才展示)
    #   - "开通会员免费看"    (price_type='member_only' 时)
    return DENY_WITH_TRIAL(preview_sec=video.preview_sec,
                           buy_options=video.buy_options_for(user))
```

### 4.5.2 定价权开放给创作者 🆕 v1.2

```
定价权归属: creator_account.pricing_mode
═══════════════════════════════════════════════

pricing_mode = 'self'   → 创作者自助定价 (默认)
pricing_mode = 'platform' → 平台运营后台统一定价 (特殊合规视频)

创作者定价审核流:
═══════════════════════════════════════════════

创作者提交 price_amount
    │
    ▼
校验 1: creator_account.pricing_enabled = 1 ?
    │ 否 → 拒绝, 提示"该账号暂不支持自助定价"
    │
    ▼
校验 2: price_amount 在 [price_amount_min, price_amount_max] 区间内 ?
        (NULL 表示走平台全局默认, 从 sys_dict 读取)
    │ 超出 → price_status='pending' → 人工审核
    │
    ▼
校验 3: creator_account.auto_publish_price = 1 ?
    │ 是 → price_status='approved' → 自动生效 ✅
    │ 否 → price_status='pending' → 人工审核
    │
    ▼ (pending 时)
平台运营后台审核
    │ 驳回 → price_status='rejected' + price_audit_remark
    │ 通过 → price_status='approved' → 生效 ✅

定价权限推荐默认值 (可在 sys_dict 维护):
═══════════════════════════════════════════════

等级     | pricing_enabled | price_amount_min | price_amount_max | auto_publish_price
---------|-----------------|------------------|------------------|-------------------
L1 (新人) | 1               | ¥1.00            | ¥50.00           | 0 (超出默认区间需审核)
L2 (普通) | 1               | ¥1.00            | ¥99.00           | 1 (区间内自动生效)
L3 (优质) | 1               | ¥1.00            | ¥199.00          | 1
L4 (头部) | 1               | ¥1.00            | ¥499.00          | 1
L5 (顶级) | 1               | ¥1.00            | 不限             | 1 + 平台抽检

注: 以上为推荐默认值, 实际区间由平台运营动态调整, 存 sys_dict 或平台配置表, 不硬编码
```

### 4.5.2.1 三级定价层级 (episode / series / creator)

```
创作者有 3 个层级可以独立定价, 全部由创作者自己设置, 平台独立区间审核:
═══════════════════════════════════════════════════════════════════════════

层级        | 表                                   | 字段                          | 价格设置者       | 定价审核区间                               | 典型价格 (L3创作者)
------------|--------------------------------------|-------------------------------|-----------------|-------------------------------------------|---------------------
episode     | stream_video                         | price_amount                  | 创作者自己定价   | creator_account.price_amount_min/max      | ¥15.00 (单集)
series      | stream_video_collection              | price_amount                  | 创作者自己定价   | creator_account.series_price_min/max      | ¥199.00 (整部剧)
creator     | creator_account                      | global_unlock_price           | 创作者自己定价   | creator_account.global_unlock_price_min/max| ¥388.00 (全部内容)

区间关系 (推荐, 不是硬约束, 可动态调整):
  price_amount_min ≤ episode ≤ price_amount_max
  series_price_min ≤ series ≤ series_price_max
  global_unlock_price_min ≤ creator ≤ global_unlock_price_max

  且通常: creator > 所有 series > 所有 episode 总和 × 80%
  即: 创作者全局 > 剧集打包 > 单集逐集全买
  这样用户有动力买打包, 创作者赚更多, 平台也降低支付手续费

定价审核流 (三级统一):
═══════════════════════════════════════════════

创作者在后台修改任何一级的 price_amount:
  ① pricing_enabled = 1 ?  (总开关)
  ② price_amount 在对应层级的 [min, max] 区间内 ?
     episode  → 查 price_amount_min/max
     series   → 查 series_price_min/max
     creator  → 查 global_unlock_price_min/max
  ③ auto_publish_price = 1 + 在区间内 → price_status='approved' → 自动生效 ✅
  ④ 超出区间 或 auto_publish_price=0 → price_status='pending' → 人工审核

三级定价区间推荐默认值 (sys_dict 维护, 不硬编码):
═══════════════════════════════════════════════

等级     | episode_min/max | series_min/max | global_min/max
---------|-----------------|----------------|-----------------
L1 (新人) | ¥1 / ¥50        | ¥10 / ¥200     | ¥100 / ¥500
L2 (普通) | ¥1 / ¥99        | ¥10 / ¥500     | ¥200 / ¥1000
L3 (优质) | ¥1 / ¥199       | ¥20 / ¥1000    | ¥300 / ¥2000
L4 (头部) | ¥1 / ¥499       | ¥50 / ¥3000    | ¥500 / ¥5000
L5 (顶级) | ¥1 / 不限       | ¥50 / 不限     | ¥500 / 不限 + 平台抽检

注: 以上是推荐默认值, 实际区间由平台运营动态调整, 存 sys_dict 或平台配置表
```

### 4.5.3 平台固定点数抽成 🆕 v1.2

```
抽成规则 (平台抽固定点数, 不同创作者独立配置)
═══════════════════════════════════════════════

公式:
  creator_share   = order_amount × revenue_rate_snapshot / 100
  platform_share  = order_amount × (1 - revenue_rate_snapshot / 100)

示例:
  创作者 A (L1):  revenue_rate_snapshot=30% → 用户付 ¥15 → 创作者 ¥4.50 / 平台 ¥10.50
  创作者 B (L4爆款): revenue_rate_snapshot=50% → 用户付 ¥15 → 创作者 ¥7.50 / 平台 ¥7.50

抽成比例谁设:
  · 默认值按等级: L1=30%, L2=35%, L3=40%, L4=50%, L5=可谈
  · 创作者 level 升级时 creator_account.revenue_rate 可自动调整
  · 运营后台可手动覆写任何创作者的 revenue_rate (签约合作场景)

生效时点 (关键):
═══════════════════════════════════════════════
抽成比例不是实时查 creator_account.revenue_rate, 而是在【视频发布时】固化:

  video.publish_status → published
      │
      ▼
  stream_video.revenue_rate_snapshot
    = creator_account.revenue_rate  (当前值)
  stream_video.subscription_revenue_rate_snapshot
    = creator_account.subscription_revenue_rate

后续创作者升级/L4签约拿到更高抽成 → 只影响新发布视频, 历史已发布视频的分润仍然用发布时的 snapshot

为什么要固化?
  ① 可审计: 每条 stream_revenue_record.revenue_rate 对应发布时的真实协议
  ② 稳定: 创作者今天 30% 明天谈成 50%, 不影响昨天那批视频的分润
  ③ 对账简单: 分润逻辑不随时间漂移

stream_revenue_record 写入时:
  revenue_rate = video.revenue_rate_snapshot  (不是 creator_account.revenue_rate!)
```

### 4.5.4 剧集解锁的代码层权限判断

```
用户请求播放某视频 video_id = 12345:
═══════════════════════════════════════════════

① 查询该视频所属剧集:
   SELECT collection_id FROM stream_video_collection_rel WHERE video_id = 12345
   → collection_id = 789 (可能 0 个或多个, 短剧通常只属于 1 个剧集)

② 查购买记录 (三条 OR + 全局解锁独立表):
   -- 先查全局解锁 (独立表, 优先级最高)
   SELECT * FROM stream_creator_unlock
   WHERE user_id = ? AND creator_id = ? AND (expires_at IS NULL OR expires_at > NOW())

   -- 再查 purchase 表 (单集 + 剧集)
   SELECT * FROM stream_video_purchase
   WHERE user_id = ? AND (
     (video_id = 12345 AND unlock_scope = 'episode')         -- 路径⑤: 单集买了
     OR (collection_id = 789 AND unlock_scope = 'collection') -- 路径④: 剧集解锁了
   )

③ 剧集价格通常低于逐集购买总价 (激励用户买全集):
   collection.price_amount = 199 (16 集打包)
   video.price_amount = 15 (每集单独)
   前端展示: 剧集详情页 → "全集解锁 ¥199 / 单集 ¥15"
   用户可能买全集 (省 41 元) 也可能只买某几集 (按需付费)

④ 剧集解锁后, 剧集内新增的视频自动解锁 (不需要补 purchase 记录):
   -- rel 表新增一条 → 用户下次播新视频时, 上述 SQL 自动匹配到 collection_id
   INSERT INTO stream_video_collection_rel VALUES (new_episode, collection_id=789)
```

### 5.3 分润结算（双轨模式）

本平台分润从 v1.1 起支持**两种模式并存**，通过 `stream_video.price_type` 区分：

| price_type | 分润模式 | revenue_source | 触发时机 | 核心逻辑 |
|-----------|---------|----------------|---------|---------|
| `paid` | 交易驱动 | DIRECT | 用户付费瞬间 (payment.success MQ) | `creator_share = order_amount × creator.revenue_rate` |
| `member_only` | 订阅池驱动 | SUBSCRIPTION_POOL | 每月 1 日 XXL-JOB 跑批 | `creator_share = pool_amount × contribution_pct × creator.subscription_revenue_rate` |
| `free` | 无分润 | — | — | 上传自由内容（靠广告/打赏，本期不做） |

#### 5.3.1 交易驱动（DIRECT，v1.0 原有逻辑不变）

```
stream-service (MQ Consumer)
    │ 消费 payment.success (business_type = stream_video_purchase)
    │ 读取 creator_account.revenue_rate (默认 30%)
    │ 计算:
    │   platform_share = total_amount × (1 - revenue_rate/100)
    │   creator_share  = total_amount - platform_share
    │ 写入 stream_revenue_record (revenue_source=DIRECT)
    │ 更新 stream_creator_earnings (available_balance += creator_share)
```

#### 5.3.2 订阅池驱动（SUBSCRIPTION_POOL，v1.1 新增）

详见 **5.4 会员订阅池分润闭环**。

#### 5.3.3 共同的月度结算

```
XXL-JOB settlement.monthly (每月 1 日 03:00)
    │ 汇总上月 stream_revenue_record
    │ 分别按 revenue_source 生成 DIRECT 和 SUBSCRIPTION_POOL 两类结算批次
    │ 创作者申请 withdrawal_request
    │ 平台审核 → Feign payment 企业付款 (pay_out)
    │ 更新 stream_revenue_record.settle_status=settled
```

对账锚点（月度校验，任一不匹配触发 discrepancy）：

```
DIRECT:
  SUM(revenue_record WHERE source=DIRECT)
    = SUM(ai_payment_order WHERE business_type=stream_video_purchase AND status=paid)
    × avg_revenue_rate

SUBSCRIPTION_POOL:
  SUM(revenue_record WHERE source=SUBSCRIPTION_POOL AND pool_batch_no='2026-09_cn')
    = SUM(creator_monthly_contribution.creator_share_amount WHERE pool_id IN (...))
    = stream_subscription_pool.creator_payout_amount  ✅ 三者必须相等
```

### 5.4 会员订阅池分润闭环（v1.1 新增）

> Netflix 式 "全平台会员订阅 → 每月总池 → 按播放量贡献分摊" 分润模式。
> 核心设计：**实时埋点 + 月度跑批 + 参数快照**，确保月度分润可复现、可审计。

#### 5.4.1 为什么需要订阅池

| 维度 | 交易驱动（DIRECT） | 订阅池驱动（SUBSCRIPTION_POOL） |
|------|-------------------|-------------------------------|
| 谁付钱 | 下单用户 | 所有订阅会员的月费总池 |
| 分润依据 | 某笔订单金额 × 固定比例 | 该创作者播放量占全平台的 % × 池子里的钱 |
| 创作者定价 | 自主定价 `price_amount` | 不单独定价，视频统一进池 |
| 长尾创作者 | 没人买就零收入 | 有人看就能拿到基本分润 |
| 爆款激励 | 爆款直接爆赚 | 爆款贡献度高但边际递减 |
| 合规对账 | 每笔订单有明确来源 | 月度池分摊，需对账锚点 |
| 适合阶段 | Phase 1 MVP | Phase 3 视频量起来后 |

```
┌───────────────────────────────────────────────────────────────────────┐
│ 实时层（用户行为埋点）                                                │
│                                                                       │
│ 用户看 member_only 视频 (price_type='member_only')                    │

│   │ 1. 校验 active 订阅会员 (Redis 缓存 stream_user_subscription)     │

│                                                                       │

                                    │

┌───────────────────────────────────────────────────────────────────────┐

│                                                                       │
│ ① 创建/锁定 stream_subscription_pool (status=pending)                │

│                                                                       │

│                      AND status='paid')                               │
│    → total_subscription_amount                                        │
│    → pool_amount = total_subscription_amount × pool_fee_rate_snapshot │

│    WHERE is_effective=1 AND is_member_view=1                          │

│    原始数据:                                                          │

│                                                                       │
│    写入 stream_revenue_record:                                        │
│      revenue_source='SUBSCRIPTION_POOL'                               │
```

#### 5.4.3 贡献度算法（三种可选模式）

订阅方案 `stream_subscription_plan.contribution_mode` 可配置，跑批时固化快照到 pool：

| mode | 公式 | 适用场景 |
|------|------|---------|
| `play_duration` | `score = Σ(有效播放秒数)` | 默认模式，时长为王，防止刷播放计数 |
| `completion_score` | `score = Σ(播放次数 × 完播率)` | 看重内容质量（完播率），鼓励短平快高质量内容 |
| `hybrid` | `score = duration_term × (1-cw) + completion_term × cw` | 混合，权重由 `completion_weight` 控制 (默认 0.3) |

**防刷机制**：
- `min_effective_sec=10`：< 10s 的播放不计入贡献（误触防护）
- `completion_rate=0` 不计入
- `total_unique_viewers` 作为辅助指标（看板展示，不参与分润公式，但可用于人工审计）
- CDN 日志交叉校验（Phase 4）

#### 5.4.4 订阅方案财务参数

```
stream_subscription_plan:
  pool_fee_rate = 1.0000    → 100% 订阅费进池 (默认, 平台不额外抽成)
                              可改成 0.9000 → 90%进池, 10%平台抽成

  creator_payout_rate = 0.7000 → 池中 70% 给创作者, 30% 留平台
                                  (pool_amount × 0.70 = creator_payout_amount)

  最终创作者分润:
    creator_share = creator_payout_amount
                  × contribution_pct           // 该创作者占比
                  × subscription_revenue_rate/100  // 该创作者订阅场景比例
```

```

  - 内嵌 video_id + user_id 防止串用
  - 签名 key 独立存储 (AES-GCM 加密)
```

## 十三、设计决策记录

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| D1 | 支付模块归属 | 独立 payment 公共服务 | 未来 billing（AI 充值）、creator（提现）都要走，抽出来复用 |
| D2 | 创作者 vs 消费者拆分 | creator + stream 两个独立模块 | 业务边界清晰：创作者后台 vs 用户前台 |
| D3 | 存储策略 | 全内容一套 bucket（stream-published） | 全平台都是 18+，不分 safe/adult，简化存储 |
| D4 | 转码方案 | 自建 FFmpeg Worker 起步 | 日活 1000，成本最低、可控性最强 |
| D5 | 对象存储 | 国内 MinIO / 国际 AWS S3 | 现有基础设施复用 + 国际合规 |
| D6 | CDN | 国内阿里云 CDN / 国际 CloudFront | CloudFront 对18+ 内容政策清晰，Geo-Restriction 开箱即用 |
| D7 | 自动审核阈值 | 0.85-0.90 灰色区间，0.90+ 直接驳回 | 正常18+ 内容 nsfw 0.6 左右，0.90+ 是极端内容 |
| D8 | 用户年龄验证 | 注册强制（国内身份证 / 国际 Sumsub 或信用卡预授权） | 未通过验证 = 完全无法使用 |
| D9 | 签名 URL 策略 | 15min + IP 绑定 + Referer 防盗链 | 防 URL 泄露 + 防未成年绕过 |
| D10 | DB 表命名 | `creator_*` / `stream_*` / `ai_payment_*` | 域前缀清晰，与已有 `sys_*` / `portal_*` / `ai_*` 风格一致 |
| D11 | 分润双轨 | 交易驱动 (DIRECT) + 订阅池 (SUBSCRIPTION_POOL) 通过 `stream_video.price_type` 区分 | 满足"单视频 PPV 付费"和"全平台会员订阅 → 按播放量分润"两种商业模式并存 |
| D12 | 订阅池分润锚点 | stream_revenue_record / creator_monthly_contribution / subscription_pool 三者 SUM 必须相等 | 月度对账时三重校验，任一不匹配自动触发 discrepancy 异常告警 |
| D13 | 贡献度算法 | 三种可配模式 (play_duration / completion_score / hybrid) + 月度固化快照 | 跑批时把 plan 参数快照到 pool 表，确保分润可复现，中途改配置不追溯 |
| D14 | Play_history 埋点 | is_effective + completion_rate + is_member_view 三字段 | 实时层把"这条播放是否算订阅池贡献"的判断在用户观看时就打上标记，月度跑批只做聚合不做二次判断 |
| D15 | 每集定价 + 定价权开放 | creator_account.pricing_mode=self + stream_video.price_amount 每集独立定价 | 创作者可自助定价，平台设区间 + 自动风控审核 |
| D16 | 平台固定点数抽成，独立可配 | creator_account.revenue_rate 不同创作者独立配置 (L1 默认 30%, L4 爆款可谈 50%+) | 抽成是创作者和平台的商业协议，必须独立可配 |
| D17 | 抽成比例快照 | 视频发布时固化到 stream_video.revenue_rate_snapshot，后续改比例不追溯 | 保证每条分润流水可审计、可追溯，不随时间漂移 |
| D18 | 剧集解锁代码层判断 | purchase.unlock_scope='collection' + 查 collection_rel 关联 | 剧集解锁后自动授予所有集观看权限，新增的集也自动解锁 |
| D19 | 创作者全局解锁独立表 | stream_creator_unlock + creator_account.global_unlock_price (价格由创作者自己定) | 全局解锁是创作者维度，不是剧集维度，独立表权限判断时优先匹配；解锁后未来新发布视频自动继承权限 |
| D20 | 三级定价层级 (episode/series/creator) | 三级定价均由创作者自己设置，creator_account 独立区间审核 (price_amount_min/max + series_price_min/max + global_unlock_price_min/max) | 剧集 Series = stream_video_collection (加 series_code/season 支持多季)；三级区间独立配置，creator 全局 ≥ 所有 series 打包 ≥ 所有 episode 逐集全买 |
| D21 | 会员权益三层叠加 | 全局免费 (stream_platform_config.free_episodes_per_series, 平台方设) + 会员集级扩展 (plan.free_episode_extra) + 秒级扩展 (plan.preview_sec_extra) + 充值送积分 (plan.gift_points + bonus) | free_episodes_per_series 是平台级全局配置，所有用户共享；会员权益在全局基础上叠加，不同 plan 可不同值 |
