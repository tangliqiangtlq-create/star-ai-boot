## 二、业务域详解

### 2.1 视频/图片生成域 (star-ai-module-generate)

#### 核心功能

| 能力 | API 示例 | 说明 |
|------|---------|------|
| 文生视频 | `POST /videos/generate` | T2V：输入 Prompt 生成视频 |
| 图生视频 | `POST /videos/generate` | I2V：输入参考图 + Prompt |
| 多参考图 | `POST /videos/generate` | 多参考图组合 + Prompt |
| 参数化生成 | `POST /generate-with-params` | 带分辨率/时长/帧数等参数 |
| 批量生成 | `POST /batch-generate-video` | 批量任务提交 |
| 生成记录 | `GET /generations` | 用户生成历史 |
| 视频超分辨率 | `POST /tools/video-upscale` | 工具链：低分辨率 → 高分辨率 |
| 字幕擦除 | `POST /tools/subtitle-erase` | 工具链：去除视频字幕 |

#### 异步任务五态流转

```
          ┌──────────┐
          │ pending   │ ← 用户提交任务
          └────┬─────┘
               │ Worker 消费
               ▼
          ┌──────────┐
          │ processing│ ← 调用 AI 厂商 API
          └────┬─────┘
         ┌─────┼─────┐
         ▼     ▼     ▼
  ┌────────┐ ┌──────┐ ┌────────┐
  │completed│ │failed│ │cancelled│
  └────────┘ └──────┘ └────────┘
         │       │
    退还余额   记录错误原因
         │       │
         ▼       ▼
    WebSocket 推送完成
```

#### 任务状态码

| 状态 | 说明 | 后续动作 |
|------|------|---------|
| `pending` | 已入队待处理 | Worker 拉取 |
| `processing` | 处理中 | 轮询/回调 AI 厂商 |
| `completed` | 成功完成 | 下载素材、转存 MinIO、推送通知 |
| `failed` | 失败 | 退还计费余额、记录错误 |
| `cancelled` | 用户取消 | 立即终止 Worker、退还余额 |

#### 通道管理架构

```
┌────────────────────────────────────────────────────────┐
│              Provider (供应商)                           │
│  ├── 厂商名称 (ByteDance / Alibaba / Kling / OpenAI ...) │
│  ├── API Base URL                                        │
│  ├── Auth 方式 (Bearer / Signature ...)                  │
│  └── 默认超时/重试配置                                    │
└────────────────────────┬───────────────────────────────┘
                         │ 1:N
┌────────────────────────▼───────────────────────────────┐
│              Channel (API 通道)                          │
│  ├── AK / SK (AES-256-GCM-SIV 加密存储)                 │
│  ├── Endpoint URL (可覆盖 Provider 默认)                 │
│  ├── Team 绑定 (租户级通道)                              │
│  ├── 负载权重                                           │
│  ├── 健康状态 (active / degraded / offline)             │
│  └── 失败计数器 → 自动熔断                               │
└────────────────────────┬───────────────────────────────┘
                         │ N:N
┌────────────────────────▼───────────────────────────────┐
│              Model (AI 模型)                            │
│  ├── 模型 ID (wan2.6-t2v / seedance-2-5 ...)            │
│  ├── 输入类型 (t2v / i2v / kf2v / image)                │
│  ├── 支持分辨率列表                                      │
│  ├── 预估时长 (秒)                                       │
│  └── 是否支持多参考图                                    │
└────────────────────────────────────────────────────────┘
```

#### 通道选择策略

```
Generate Request
      │
      ▼
Provider Module Route Service
      │
      ├── LoadBalance: 同一 Provider 多个 Channel 按权重选择
      ├── Failover:    首选失败 → 自动降级到备用 Channel
      ├── TeamScope:   优先使用 Team 绑定的专属 Channel
      └── HealthCheck: 跳过 offline/degraded 状态的 Channel
```

### 2.4 计费订阅域 (star-ai-module-billing)

#### 计费模型

```
计费类型
  ├── 按量计费 (Pay-as-you-go)
  │   └── 每生成一条视频扣减 Credits
  ├── 订阅套餐 (Subscription Plan)
  │   └── 月度/季度/年度套餐，固定 Credits
  └── 充值 (Prepaid Recharge)
      └── 单次购买 Credits

定价维度
  ├── 按模型 (wan2.6-t2v ≠ wan2.2-t2v)
  ├── 按分辨率 (720p ≠ 1080p ≠ 4K)
  ├── 按时长 (每秒累加)
  ├── 优惠码 (Discount Code)
  └── 兜底单价 (Fallback Price，未配置分辨率时)

支付渠道
  ├── 微信支付
  ├── 支付宝
  ├── 对公打款 (Invoice/账单)
  └── API Key / 企业账户
```

#### 余额与配额

```
用户余额 (Account Balance)
  ├── Personal Allowance (个人可用额度)
  └── Team Balance (团队共享余额)

团队控费
  ├── 员工消费限额 (per-user cost limit)
  ├── 项目成本上限 (story/project cost limit)
  ├── 余额阈值告警 (邮件 + 飞书通知)
  ├── 用量统计报表
  └── 审核日志 (谁花了多少钱)

扣费时机
  ├── 生成前预扣 (Reservation)
  ├── 完成后实扣 (Deduction)
  └── 失败/取消退还 (Refund)
```

## 三、端到端业务流程

### 3.1 视频生成完整时序

```
Client (Next.js SPA)
    │
    │  1. POST /videos/generate { prompt, model_id, references: [] }
    │
    ▼
API Gateway (star-ai-cloud-gateway:9999)
    │  2. GlobalAccessTokenFilter 校验 JWT
    │  3. Sentinel 限流检查
    │
    ▼
Generate Service
    │  4. 鉴权 (Sa-Token)
    │  5. 计费检查 (Feign → Billing: 查询余额)
    │  6. 预扣余额 (Reservation)
    │  7. 创建 Generation record (status=pending)
    │  8. 构建 Prompt + 替换素材占位符
    │  9. 投递异步任务 (Feign → Task)
    │
    ▼
Task Service
    │  10. 任务入队 Redis (Bull)
    │  11. 返回 Task ID
    │
    ▼
Worker 异步执行
    │  12. 消费任务 (Redis POP)
    │  13. 调用 Provider Route Service
    │
    ▼
Provider Service
    │  14. LoadBalance 选 Channel
    │  15. 读取 AK/SK (AES-GCM-SIV 解密)
    │  16. 构造请求 + 签名
    │
    ▼
AI 厂商 API (火山/阿里/快手/OpenAI/Google)
    │  17. 返回 TaskID / VideoURL
    │
    ▼
Worker 轮询
    │  18. 每 10s 查询任务状态
    │  19. 完成 → 下载视频
    │  20. 上传 MinIO
    │  21. 更新 DB status=completed
    │
    ▼
Billing Service
    │  22. 实扣余额 (Deduction)
    │
    ▼
Client WebSocket
    │  23. 推送 { generation_id, status: "completed", video_url }
    │
    ▼
前端渲染视频
```

### 3.2 剧本→分镜→视频全链路

```
Step 1: 用户输入故事大纲
  POST /scripts/generate → AI 生成剧本文本

Step 2: 剧本 → 分镜
  POST /storyboards/generate
    → AI 拆分镜头 (shot list)
    → 为每个镜头生成 Prompt
    → 自动填充素材占位符

Step 3: 分镜 → 素材选择
  用户为每个镜头选择 角色/场景/道具 素材
    → 占位符替换为实际素材引用

Step 4: 分镜 → 视频生成
  POST /videos/generate (每个镜头)
    → Worker 批量调用 AI 厂商 API
    → 生成镜头视频序列

Step 5: 时间线合成
  POST /storyboard-projects/{id}/compile
    → 拼接镜头序列
    → 添加字幕 (POST /tools/subtitle-erase 擦除 AI 原始字幕)
    → 超分辨率 (POST /tools/video-upscale)

Step 6: 输出
  合成完整短剧 → 用户下载/分享
```

### 5.4 自动审核 Pipeline

```
上传完成 (stream-creator-draft)
    │
    ▼
FFmpeg 抽帧 (每 5s 一帧)
    │
    ▼
帧级 NSFW 检测
    ├── 国内: 阿里云内容安全
    └── 国际: Sightengine / NudeNet (自部署)
    │
    ▼
nsfw_score = max(all_frames)
    │
    ├── > 0.90 → rejected (直接驳回，不走人工)
    ├── < 0.85 → auto_passed (自动通过)
    └── 0.85-0.90 → flagged (人工复核)
    │
    ▼
审核通过 → COPY draft → stream-published
审核驳回 → 30天后 draft 自动清理
```

### 5.5 三级定价层级（创作者自助定价 + 平台区间审核）v1.2 核心

创作者有 **3 个独立层级**可定价，全部由创作者自己设置，平台独立区间审核：

| 层级 | 表 | 字段 | 典型价格 | 审核区间 |
|------|-----|------|---------|---------|
| **episode 单集** | stream_video | price_amount | ¥15.00 | creator.price_amount_min/max |
| **series 剧集** | stream_video_collection | price_amount | ¥199.00 | creator.series_price_min/max |
| **creator 全局** | creator_account | global_unlock_price | ¥388.00 | creator.global_unlock_price_min/max |

推荐价格约束（保证打包更便宜，激励用户）：`creator ≥ 所有 series ≥ 所有 episode 逐集全买 × 80%`

**定价审核流**：创作者提交 → `pricing_enabled=1` → 在对应区间内 + `auto_publish_price=1` → `price_status='approved'` 自动生效；否则 `price_status='pending'` 人工审核。

### 5.6 五种消费路径（权限判断优先级）

用户请求播放某视频时，stream-service 按以下优先级判定观看权限（从上到下首个命中即放行）：

```
① 免费: stream_video.price_type = 'free'
② 全局免费集数: video 在剧集内 + episode_number ≤ stream_platform_config.free_episodes_per_series
③ 会员免费: price_type='member_only' + active 订阅会员 (贡献计入订阅池)
④ 会员集级扩展: global_free_n + plan.free_episode_extra (叠加层, 如 3+5=8 集)
⑤ 创作者全局解锁: stream_creator_unlock.exists(user, creator_id) → 永久解锁该创作者所有视频 (含未来新发布的)
⑥ 剧集解锁: stream_video_purchase (collection_id, unlock_scope='collection') → 永久解锁该剧集 (含未来新增的集)
⑦ 单集购买: stream_video_purchase (video_id, unlock_scope='episode') → 永久解锁该单集
```

前端引导（视频详情页，用户未解锁时）：
```
[试看 30s]
[买这一集 ¥15]            ← path ⑦
[解锁整部剧集 ¥199]        ← path ⑥
[解锁该创作者全部 ¥388]    ← path ⑤ (global_unlock_enabled=1 时才展示)
[开通会员免费看]           ← path ③ (price_type='member_only' 时)
```

### 5.8 分润结算（双轨模式 v1.2.1 · 抽成快照）

本平台分润支持**双轨并存**，交易驱动 DIRECT + 订阅池驱动 SUBSCRIPTION_POOL：

| 定价层级 | 分润模式 | revenue_source | 抽成比例来源 | 触发时机 |
|----------|---------|----------------|------------|---------|
| 单集 (paid) | 交易驱动 | DIRECT | stream_video.revenue_rate_snapshot | 用户付费瞬间 (payment.success MQ) |
| 剧集 (paid) | 交易驱动 | DIRECT | stream_video_collection.revenue_rate_snapshot | 剧集解锁支付成功 (MQ) |
| 全局 (creator) | 交易驱动 | DIRECT | creator_account.revenue_rate (支付时实时取, 无发布概念) | 全局解锁支付成功 (MQ) |
| 会员 (member_only) | 订阅池驱动 | SUBSCRIPTION_POOL | creator.subscription_revenue_rate_snapshot | 每月 1 日 XXL-JOB `subscription.pool.aggregate` |

**抽成快照（v1.2 关键设计）**：抽成比例不是实时查 creator_account，而是在**视频发布时**固化到 `stream_video.revenue_rate_snapshot` / `stream_video_collection.revenue_rate_snapshot`。后续创作者升级拿更高抽成，不影响历史已发布视频的分润——保证每条流水可审计可追溯。

**交易驱动 DIRECT 完整链路**：
```
用户支付成功 (payment.success MQ)
  │ 读取 revenue_rate_snapshot
  │ 写入 stream_revenue_record:
  │   revenue_source = DIRECT
  │   creator_share   = order_amount × revenue_rate_snapshot / 100
  │   platform_share  = order_amount × (1 - revenue_rate_snapshot / 100)
  │   video_id / collection_id / creator_id → 标识哪级消费
  │ 更新 stream_creator_earnings
```

**订阅池驱动 SUBSCRIPTION_POOL（每月 1 日 02:00 XXL-JOB）**：
```
① 创建/锁定 stream_subscription_pool (pool_month=上月, region 分池)
② 汇总 ai_payment_order (business_type LIKE 'stream_subscription%' AND status='paid')
   → pool.total_subscription_amount → pool_amount × pool_fee_rate
③ 聚合 stream_video_play_history (is_effective=1 AND is_member_view=1)
   → stream_creator_monthly_contribution.contribution_score + contribution_pct
④ 分摊: creator_share = pool.creator_payout_amount × contribution_pct × subscription_revenue_rate
   写入 stream_revenue_record (source=SUBSCRIPTION_POOL, pool_batch_no='YYYY-MM_region')
⑤ pool.status = 'settled'
```

**对账锚点（三重校验，任一不匹配触发 discrepancy 告警）**：
```
SUBSCRIPTION_POOL:
  SUM(revenue_record WHERE source=SUBSCRIPTION_POOL AND pool_batch_no='2026-09_cn')
    = SUM(monthly_contribution.creator_share_amount WHERE pool_id IN (...))
    = stream_subscription_pool.creator_payout_amount  ✅ 三者必须相等
```

**共同月度结算（XXL-JOB settlement.monthly 03:00）**：
```
汇总上月两类 revenue_record → 分别生成 DIRECT 和 SUBSCRIPTION_POOL 结算批次
创作者申请 withdrawal_request → 审核 → Feign payment 企业付款
```
