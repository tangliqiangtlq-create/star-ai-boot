# Star AI Boot · 系统架构总览

> 版本：v3.11.0 | 框架：JeecgBoot | 架构风格：SaaS 多租户 + Spring Cloud 微服务

---

## 一、系统定位

Star AI Boot 是基于开源企业级低代码平台 JeecgBoot 二次开发的 **AI 短剧生成 + 18+ 视频付费分润 SaaS 平台后端**，支持：

- 多 AI 厂商视频/图片生成（豆包、即梦、万相、可灵、Sora、Veo 等 15+ 模型）
- 分镜/剧本/素材库全链路创作
- 团队协作 + 细粒度 RBAC 权限
- 多维度计费与订阅
- 🆕 18+ 视频创作者上传 / HLS 流媒体播放
- 🆕 **三级定价 + 五种消费路径**：单集(episode) / 剧集(series) / 创作者全局(creator) 三级独立定价，非会员→全局免费集数→会员免费扩展→合集解锁→单集购买 五种路径
- 🆕 **固定点数抽成**：不同创作者独立配置，发布时固化快照不追溯
- 🆕 **会员订阅池分润** (Netflix 式) + **会员权益体系** (充值送积分 + 全局免费集数 + 会员扩展集数/秒数)
- 🆕 国内 + 国际双 Region 部署 / Stripe/微信双支付渠道 / 18+ 合规（自动审核、地理屏蔽、签名 URL 强制鉴权）
- 企业级安全加固（OWASP Top 10 全覆盖）

> **18+ 视频付费分润方案**：详见 [18+ 视频付费分润方案.md](18+ 视频付费分润方案.md)

### 依赖方向（单向）

```
biz → api → base-core → starter-secrets
微服务 biz  →  system-cloud-api (Feign)
网关        →  下游所有微服务

🆕 新增依赖关系:
stream  → payment (Feign 创建支付单)
stream  → creator (Feign 读取创作者信息)
creator → payment (Feign 提现打款)
creator → stream  (Feign 发布回调)
payment → system  (Feign 仅用户信息)
```

每个业务模块内部统一分为 `-api`（接口定义 + DTO）和 `-biz`（实现 + 启动类）两个子模块。

## 七、配置外部化

所有配置通过 **Nacos Config** 管理，启动链：

```
EnvironmentPostProcessor
  ├── RepoRootDotEnvEnvironmentPostProcessor   → 读取仓库根 .env
  └── MpaySecretsEnvironmentPostProcessor      → 解密 AWS KMS / 本地 AES-GCM Secrets

Spring Boot application.yml
  ├── server.port / redis / nacos discovery
  └── spring.config.import = optional:nacos:{application-name}-{profile}.yaml

Nacos 远程配置 (优先级最高)
  ├── jeecg.yaml           (公共配置)
  ├── jeecg-dev.yaml       (dev 环境覆盖)
  ├── {service}-dev.yaml   (服务专属覆盖)
  └── Sentinel 规则数据源 (Nacos DataId)
```

敏感数据（DB 密码、AK/SK、API Key）**绝对不允许**明文写入 Nacos，统一走 `star-ai-boot-starter-secrets` 解密：
- 本地开发：`LocalAesGcmSecretsCrypto`（AES-GCM-SIV）
- 生产环境：`AwsKmsDecryptor` / `HttpJsonKmsDecryptor` / `MpayKmsDecryptor` / `HuaweiCsmsKmsDecryptor`

## 八、微服务间通信

| 方式 | 场景 | 框架 |
|------|------|------|
| **Feign** | 同步调用（系统服务 → 业务模块） | Spring Cloud OpenFeign + OkHttp + Jackson |
| **RestTemplate** | 简单 HTTP 调用 | Spring Web Client |
| **RabbitMQ** | 异步解耦（扣费通知 / 审核消息 / OTP） | vhost 按服务隔离 `/mightyPay/{serviceName}` |
| **RocketMQ** | 复杂消息场景（事务消息 / 顺序消息） | RocketMQ 5.3.0 |
| **WebSocket** | 任务进度实时推送 | Servlet WebSocket |
| **Redis Pub/Sub** | 配置变更通知 / 路由刷新 | RedisTemplate.convertAndSend |
| **Gateway 内部** | 网关直接过滤 + 路由 | Spring Cloud Gateway WebFlux |

## 九、SaaS 多租户设计

多租户基于 MyBatis-Plus 的 `TenantLineInnerInterceptor` 实现行级隔离：

```java
// star-ai-boot-base-core: JeecgTenantParser
// 自动向所有 SQL 注入 WHERE tenant_id = ?
// 通过 HttpHeader "X-Tenant-Id" 或 Sa-Token 中的 TenantContext 传递
```

| 隔离维度 | 实现 |
|---------|------|
| 行级隔离 | 所有业务表带 `tenant_id` 字段，Mybatis-Plus 自动注入 |
| SaaS 路由 | `TenantContextInboundFilter` → ThreadLocal → `C4TenantLineHandler` |
| 数据源 | 同库隔离（轻量），可通过 `dynamic-datasource` 扩展库级隔离 |
| 权限隔离 | 每个租户独立 Role/Permission 树 |
| 配额隔离 | `SysTenantPack` + `SysTenantPackUser` 套餐包绑定 |

## 十、架构设计原则

| 原则 | 体现 |
|------|------|
| **单一职责** | 每个微服务只负责一个业务域（generate/content/billing/team/task/provider） |
| **接口隔离** | 每个模块拆 `-api` 和 `-biz`，api 层只放接口 + DTO |
| **基础设施下沉** | `star-ai-boot-base-core` 统一提供安全/日志/字典/分页/加密/防火墙 |
| **安全左移** | 启动期安全扫描 + `H8DenyAuditStartupVerifier` / `H2FeignLevelStartupVerifier` |
| **配置外部化** | Nacos + Secrets，支持 KMS/AES 双模式解密 |
| **失败隔离** | Sentinel 熔断 + Seata 分布式事务 + RabbitMQ DLX |
| **可观测性** | `management.endpoints.web.exposure=health` + 安全日志审计 |
| **合规优先** | OWASP HTML Sanitizer + ESAPI + BouncyCastle + CVE 全量扫描 |
