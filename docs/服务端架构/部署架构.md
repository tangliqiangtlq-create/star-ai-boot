# 部署架构

> Star AI Boot 采用 **Docker + Nacos + K8s** 部署体系，支持开发/测试/预发/生产四套环境。

---

## 一、环境矩阵

| 环境 | Profile | Nacos Namespace | 数据库 | Redis | RabbitMQ | 说明 |
|------|---------|----------------|--------|-------|----------|------|
| **本地开发** | `dev` | `public` | MySQL 本地 | 本地 Redis | 本地 RabbitMQ | `.env` + `application-dev.yml` |
| **测试** | `test` | `test-namespace` | 测试库 | 测试 Redis | 测试 vhost | 独立资源 |
| **预发** | `uat` | `uat-namespace` | UAT 库 (脱敏) | UAT Redis | UAT vhost | 与生产配置对齐 |
| **生产** | `prod` | `prod-namespace` | 生产主从 | 生产 Redis 集群 | 生产 vhost 隔离 | AWS KMS / 华为 CSMS |

## 四、Dockerfile 多阶段构建

以 `star-ai-module-generate` 为例，所有业务微服务共用同一模板：

```dockerfile
# === Stage 1: Build ===
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /workspace
COPY pom.xml .
COPY star-ai-boot-base-core/ star-ai-boot-base-core/
COPY star-ai-boot-starter-secrets/ star-ai-boot-starter-secrets/
COPY star-ai-module-system/ star-ai-module-system/
COPY star-ai-server-cloud/ star-ai-server-cloud/

# 先 install 公共模块，利用 Docker 层缓存
RUN mvn -pl star-ai-boot-base-core,star-ai-boot-starter-secrets,star-ai-module-system -am install -DskipTests -T 1C

# 构建目标模块
WORKDIR /workspace/star-ai-server-cloud/star-ai-module-generate/star-ai-module-generate-biz
RUN mvn package -DskipTests -o

# === Stage 2: Runtime ===
FROM eclipse-temurin:17-jre-alpine AS runtime

# 创建非 root 用户
RUN addgroup -S appgroup && adduser -S appuser -G appgroup

WORKDIR /app

# 复制 jar
COPY --from=builder --chown=appuser:appgroup \
  /workspace/star-ai-server-cloud/star-ai-module-generate/star-ai-module-generate-biz/target/star-ai-module-generate-biz.jar \
  app.jar

# JVM 参数
ENV JAVA_OPTS="-Xms1g -Xmx2g -XX:+UseG1GC -XX:MaxGCPauseMillis=200"

USER appuser

EXPOSE 8080

# Graceful Shutdown
HEALTHCHECK --interval=30s --timeout=10s --start-period=60s --retries=3 \
  CMD wget -qO- http://localhost:8080/actuator/health || exit 1

ENTRYPOINT ["sh", "-c", "java ${JAVA_OPTS} -jar app.jar"]
```

### 4.1 安全加固

| 项 | 值 | 说明 |
|----|-----|------|
| 基础镜像 | `eclipse-temurin:17-jre-alpine` | Alpine 最小镜像，攻击面小 |
| 运行用户 | `appuser` (非 root) | 禁止容器以 root 运行 |
| Jar 权限 | 644，非写 | 防止运行时被篡改 |
| DB 密码 | K8s Secret 注入 | 不在镜像中硬编码 |
| 构建时间 | 多层缓存 | 加速 CI/CD |

## 六、灰度发布策略

```
Canary Release (金丝雀)
  │
  ├── Replicas: 当前 N → N+1 → 观察 → 再 N+1 → ...
  ├── Sentinel Dynamic Rule (Nacos)
  │   dataId: {service}-canary-rules
  │   流量分配：header 匹配 + 百分比
  │
  └── 自动回滚触发条件
      ├── P99 延迟 > 3x 基线
      ├── 5xx 错误率 > 2%
      └── 数据库 Deadlock / OOM
```

### 灰度流量配置示例 (Sentinel + Nacos)

```json

      "paramKey": "X-Canary",

    }
  ]
```

## 八、备份与灾难恢复

### 8.1 备份策略

| 资源 | 频率 | 保留 | 方式 |
|------|------|------|------|
| MySQL | 全量每日 + binlog 实时 | 全量 7 天 / binlog 30 天 | mysqldump + xtrabackup |
| Redis | RDB 每小时 + AOF | 7 天 | S3 上传 |
| MinIO | 每日增量 | 30 天 | MinIO Mirror → S3 |
| Nacos | 每日配置快照 | 30 天 | MySQL dump |
| 日志 | 实时 | 14 天 | ELK / Loki |

### 8.2 灾难恢复流程

```
Step 1: 检测故障 (Prometheus Alert / PagerDuty)
Step 2: 通知 on-call (企业微信 + 短信 + 电话)
Step 3: 判断故障级别
  ├── Pod 级 (单实例 OOM) → K8s 自动重启 / 手动 scale-out
  ├── 服务级 (全服务挂)   → 回滚镜像版本
  ├── 数据库级             → 切换从库 / 恢复备份
  └── 机房级               → 切灾备机房 (多活)
Step 4: 恢复后验证 (Smoke Test)
Step 5: Post-Mortem (根因分析)
```
